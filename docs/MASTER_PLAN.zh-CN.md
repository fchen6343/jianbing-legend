# 《煎饼摊传奇》完整版游戏开发总指令

## 一、你的角色与总体任务

你是一支专业独立游戏开发团队，同时承担以下角色：

- 游戏总监与玩法策划
- 2D 卡通游戏美术设计师
- 前端游戏程序员
- 动画与交互设计师
- 游戏经济系统设计师
- 剧情与角色设计师
- 游戏测试工程师

**任务：在现有《煎饼摊传奇》项目基础上，开发一款完整、精致、有趣、能够长期游玩的中文街头美食经营网页游戏。**

参考作品：

- 《沙威玛传奇》：食品制作手感、幽默事件、快速经营节奏
- 《老爹披萨店》系列：独立界面、顾客系统、升级、长期经营
- 原创中国街头美食文化：天津煎饼果子、街边小摊、熟客人情味

参考的是设计品质和玩法逻辑，不得直接复制其他游戏的美术、代码、音乐、角色或受保护的具体设计。

### 核心目标

玩家从一辆破旧煎饼小推车起步，通过每天亲手制作煎饼、结识顾客、购买厨具、装修店铺、解锁剧情，逐渐发展成全国连锁煎饼品牌。

游戏必须同时具备：

1. 有趣的第一人称制作操作。
2. 精致统一的 2D 卡通美术。
3. 有实际意义的赚钱、升级和装修机制。
4. 会发展的角色关系与故事。
5. 不断出现的新内容、动画与惊喜。
6. 三个独立、可靠的存档。
7. 可持续游玩至少 50 个游戏日的完整内容。
8. 到达大结局后仍可继续经营。

**最重要的开发原则：每个功能必须真正影响游戏。禁止制作无法使用的装饰性按钮、假升级、空剧情或纯展示界面。**

## 二、游戏整体结构

### 2.1 完整界面架构

游戏启动后，显示独立主菜单。

主菜单包含：

- 开始游戏
- 继续游戏
- 选择存档
- 剧情回顾
- 设置
- 制作人员 / 版本信息

玩家选择存档后，进入当前游戏进度。

完整界面关系：

```text
游戏启动
│
├─ 主菜单
│   ├─ 新游戏
│   ├─ 继续游戏
│   ├─ 三个存档槽位
│   ├─ 设置
│   └─ 剧情回顾
│
└─ 选择存档
    │
    ├─ 新存档：开场剧情
    │
    └─ 已有存档：经营中心
         │
         ├─ 开始营业
         │    ├─ 第一人称制作煎饼
         │    ├─ 顾客订单
         │    ├─ 随机事件
         │    └─ 每日结算
         │
         ├─ 厨具升级屋
         ├─ 装修设计室
         ├─ 食材采购店
         ├─ 熟客关系簿
         ├─ 街坊故事
         ├─ 食谱与图鉴
         ├─ 成就与收藏室
         ├─ 连锁分店管理
         └─ 设置及存档
```

### 2.2 界面隔离原则

**玩家制作煎饼时，屏幕必须专注于煎饼制作。**

绝对不要把以下内容一直堆在制作界面：

- 厨具升级卡片
- 家具商城
- 大型经营报表
- 熟客详细档案
- 成就列表
- 分店管理系统

这些功能应该全部进入独立场景。

日常营业画面只保留：

- 第一人称煎饼制作台
- 顾客和订单气泡
- 当前金币
- 营业倒计时
- 必要的库存信息
- 暂停按钮
- 交互提示

风格统一为明亮、精致、带有中国街头烟火气的 2D 卡通。

## 三、游戏完整日常循环

### 3.1 一天的流程

```text
清晨
 ↓
经营中心
 ↓
查看顾客消息及当天预告
 ↓
购买食材 / 升级厨具 / 装修
 ↓
点击「开始营业」
 ↓
3–5 分钟制作煎饼
 ↓
处理特殊顾客及随机事件
 ↓
收摊
 ↓
每日营业结算动画
 ↓
熟客互动 / 剧情 / 奖励
 ↓
返回经营中心
 ↓
进入下一天
```

### 3.2 每日营业时间

初始设置：

- 标准营业时长：240 秒
- 每天约 10–14 位顾客
- 随着店铺升级，顾客数量和订单复杂度适当增加
- 休闲难度，不设置破产或强制 Game Over
- 顾客耐心可以影响小费和评价，但不应造成过大的经济惩罚
- 对话、暂停和剧情期间，营业计时停止

玩家可以在设置中调整营业节奏，但默认保证每局约 3–5 分钟。

### 3.3 每日结算

收摊后显示完整结算动画，包含：

- 今日营业额
- 食材成本
- 净利润
- 小费收入
- 服务顾客数量
- 顾客满意度
- 新增熟客好感度
- 新解锁内容
- 当天特殊事件

结算应有金币飞入钱箱、招牌亮灯、顾客欢呼等动画。

评价采用三星制，但低评价不阻断剧情和正常升级。

## 四、第一人称煎饼制作系统

这是游戏最重要的部分，必须优先保证制作过程好玩。

### 4.1 制作步骤

1. 舀取面糊，倒在鏊子上。
2. 使用刮板旋转摊开面糊。
3. 打鸡蛋并摊匀。
4. 按照制作进度处理饼皮。
5. 使用刷子涂抹酱料。
6. 添加葱花、香菜等配料。
7. 加入果篦儿或油条。
8. 按照顾客要求折叠煎饼。
9. 装袋交付。
10. 收取金币并评价订单。

所有关键步骤必须具有直观的反馈。

### 4.2 操作体验要求

- 面糊应该逐渐铺开，而不是突然变成一张圆形图片。
- 鸡蛋应出现打碎、蛋液流动、摊开的过程。
- 刷酱要随着鼠标移动留下涂抹痕迹。
- 果篦儿必须清晰表现出薄脆、金黄色、脆片结构。
- 油条与果篦儿外观必须明显不同。
- 折叠必须是真实的多阶段折叠动画。
- 食材放入煎饼后，应与饼皮形成正确的视觉层次。
- 所有操作需要支持鼠标；触屏交互尽量兼容。
- 制作步骤不能只靠点击按钮完成，应保留适当的拖拽、涂抹和动作反馈。

### 4.3 现有功能保留

必须保留并优化：

- 普通模式 / 天津人模式切换
- 伸缩小夹子偷吃的顾客
- 老板补货动画
- 鸡蛋摊开动画
- 新手制作教程
- 食材库存机制
- 原有顾客和订单逻辑

天津人模式必须是可自由切换的内容风格选项，不应与存档永久绑定。

新手教程需要带领玩家完整制作、交付第一套煎饼，而不是只介绍按钮。

## 五、独立厨具升级系统

### 5.1 厨具升级屋

经营中心包含一个独立的「厨具升级屋」。

进入后，看到精致的 2D 卡通厨房，所有厨具摆放在对应位置。

玩家可以点击某个厨具，打开升级面板。

面板必须显示：

- 厨具当前外观
- 当前等级
- 下一级外观预览
- 升级价格
- 升级效果
- 玩家金币余额
- 升级确认按钮

升级成功后，播放真实的设备变化动画。

### 5.2 厨具及参考价格

| 厨具 | 初始升级价格 | 升级效果 |
|---|---:|---|
| 高级面糊刮板 | 180 金币 | 缩短手动摊饼时间 |
| 自动旋转刮板 | 550 金币 | 自动将面糊摊成圆形 |
| 鸡蛋辅助器 | 350 金币 | 提高打蛋效率 |
| 自动刷酱机 | 800 金币 | 自动完成刷酱 |
| 智能配料盒 | 450 金币 | 更快速拿取配料 |
| 自动折叠辅助器 | 1200 金币 | 辅助折叠部分步骤 |
| 加热鏊子 | 650 金币 | 减少等待时间 |
| 智能收银台 | 1000 金币 | 自动完成收款流程 |

价格为初始设计值，后续通过游戏测试调整。

### 5.3 自动化原则

自动化只能取代重复而繁琐的步骤，不能让煎饼制作完全失去操作乐趣。

玩家在游戏后期仍应亲手：

- 处理特殊订单
- 添加或选择关键配料
- 进行部分鸡蛋与折叠操作
- 与顾客互动
- 处理突发事件

部分自动设备可在营业前选择开启或关闭，允许玩家继续享受手动制作。

升级必须改变实际操作耗时、动画或交互过程。

## 六、装修与建筑成长系统

### 6.1 五阶段成长

| 阶段 | 建筑形式 | 预计解锁日 |
|---|---|---|
| 第一阶段 | 破旧煎饼小推车 | 第 1 天 |
| 第二阶段 | 固定街边煎饼摊 | 第 8 天左右 |
| 第三阶段 | 正式煎饼门店 | 第 18 天左右 |
| 第四阶段 | 大型特色餐厅 | 第 32 天左右 |
| 第五阶段 | 全国煎饼连锁品牌 | 第 48 天左右 |

玩家应在约 40–60 个游戏日内完成主要成长剧情。

### 6.2 建筑升级条件

建筑升级需要满足：

- 最低经营天数
- 累计营业额
- 对应主线剧情进度
- 升级所需金币

参考数值：

| 新阶段 | 累计营业额门槛 | 升级花费 |
|---|---:|---:|
| 固定街边摊 | 1200 | 300 |
| 正式门店 | 4500 | 1400 |
| 大型餐厅 | 9500 | 3500 |
| 连锁品牌 | 18000 | 7000 |

累计营业额用于解锁资格，不扣除；升级金币从当前余额扣除。

这些条件必须先通过经济模拟，确保普通玩家不用刷大量重复订单也能在预期天数完成进度。

### 6.3 装修设计室

装修系统必须是独立场景。

玩家可以购买并摆放：

- 招牌
- 灯笼
- 桌椅
- 墙面装饰
- 绿植
- 灯光
- 收银台皮肤
- 吉祥物
- 不同主题的装修套装

交互要求：

- 点击家具购买
- 拖动摆放
- 旋转或调整朝向
- 预览位置
- 检查越界及碰撞
- 确认放置
- 再次编辑或收回家具

装修需要真实反映在对应店铺场景中。

部分装饰可提供轻微的满意度、知名度或好感度加成，避免装修系统完全没有经营意义。

## 七、熟客关系与剧情系统

### 7.1 核心设计

设计至少 8 位有独立人格、外观和背景故事的熟客。

每位熟客拥有：

- 姓名与卡通形象
- 职业或身份
- 喜欢的煎饼口味
- 不喜欢的配料
- 好感度
- 专属剧情
- 对话分支
- 个人任务
- 隐藏奖励
- 图鉴资料

### 7.2 好感度规则

好感度为 0–100。

参考关系等级：

| 好感度 | 关系 |
|---|---|
| 0–19 | 陌生人 |
| 20–39 | 认识 |
| 40–59 | 常客 |
| 60–79 | 好朋友 |
| 80–100 | 挚友 |

提高好感度的方法：

- 记住顾客口味
- 正确完成订单
- 选择合适的聊天选项
- 完成专属任务
- 在特殊剧情中帮助顾客

奖励包括金币、特殊配方、装修家具、称号、隐藏剧情。

玩家不能通过反复点击同一句对话无限刷好感度。

### 7.3 初始熟客名单

**老李——退休工人**

每天准时来买煎饼，喜欢传统果篦儿。剧情围绕他和老街坊的回忆，最终赠送家传配方。

**小王——打工青年**

每天赶时间上班。随着关系发展，他可能失业并尝试创业。完成任务获得自动化设备折扣。

**张阿姨——社区消息中心**

喜欢聊天，知道街坊的大事小事。完成剧情可以提前获知节日活动与特殊顾客。

**小美——大学生**

热爱拍短视频，想成为美食博主。完成剧情获得特殊装饰和店铺知名度提升。

**刘师傅——退休厨师**

对煎饼制作要求严格。完成支线可获得隐藏配方和厨具优化灵感。

**老马——出租车司机**

每天带来不同的城市见闻。完成任务可解锁远方顾客和新的食材订单。

**神秘西装男**

最初只是沉默的普通顾客，后期发现其与连锁品牌主线有关。逐步揭露他的身份和商业目的。

**小豆——附近的小学生**

喜欢特别的煎饼组合。通过温馨故事解锁趣味煎饼和店铺吉祥物装饰。

### 7.4 对话设计

聊天采用剧情对话框，不需要连接在线大语言模型。

每位角色至少设计：

- 5 条日常闲聊
- 3 段专属剧情
- 2 个有选择分支的事件
- 1 个完整的专属任务链
- 1 项独特奖励

重要对话要有角色表情、文字逐字出现、适当动作和音效。

对话选项必须产生合理后果，但避免因为选错一句话永久锁死重要内容。

## 八、创业主线故事

### 故事基调

励志、搞笑、温馨、具有适度反转。

主线以「从一个人的小推车，到属于自己的连锁品牌」为核心。

### 第一章：一辆破车，一个梦想

开场动画：

主角带着祖传煎饼配方来到天津。

身上只有少量积蓄，以及一辆不太可靠的小推车。

第一天开张时，招牌甚至掉了下来。

随后进入完整的新手教程。

### 第二章：街坊们的味道

结识第一批熟客，获得固定顾客群。

遇到偷吃顾客、奇葩订单、突然大雨等事件。

通过积累资金获得固定摊位。

### 第三章：我的第一家店

竞争对手出现。

玩家面临装修、设备升级与顾客增加带来的新挑战。

解锁正式门店与特色配方。

### 第四章：煎饼也能做大生意

网红探店、媒体报道、节日促销、厨师挑战等事件逐步出现。

神秘投资人现身，提出合作。

玩家开始思考自己的经营理念。

### 第五章：煎饼传奇

建立属于自己的煎饼品牌。

举办大型开业庆典。

解锁连锁分店经营，完成主要创业故事。

主线结局应体现此前的熟客关系与重要选择，但不需要开发多个完全不同的游戏主线。

玩家完成结局后，可以继续制作煎饼、装修、升级、管理分店、完成图鉴和隐藏任务。

## 九、随机事件系统

设计至少 15 类随机事件，并控制出现频率。

初期事件：

- 顾客用伸缩夹偷吃
- 顾客忘带钱包
- 下雨导致客流变化
- 突然出现长队
- 熟客带朋友来
- 顾客提出奇特订单

中期事件：

- 网红探店
- 食材价格波动
- 厨具临时故障
- 社区美食比赛
- 限时特殊订单
- 老顾客请求帮助

后期事件：

- 竞争对手挑战
- 媒体采访
- 节日客流增加
- 神秘美食家评分
- 连锁店特别活动

事件必须有：

1. 出现条件和概率。
2. 对应角色或动画。
3. 玩家可执行的操作。
4. 明确的结果和反馈。
5. 合理的冷却时间。

随机事件以惊喜和幽默为主，不应频繁打断制作操作，更不能让休闲玩家反复失败。

## 十、庆祝动画与剪彩系统

### 10.1 每日收摊庆祝

根据当日成绩播放简短动画，例如：

- 老板举起钱箱
- 金币飞入储蓄罐
- 顾客鼓掌
- 店铺亮灯
- 出现「今日营业结束」卡片

时长约 3–6 秒，可以跳过。

### 10.2 五个成长阶段的演出

**小推车开业**

主角自己贴上手写招牌，简单放一串小鞭炮。

**固定街边摊**

几名熟客带来彩带，简单剪彩，街坊鼓掌。

**正式门店**

邀请街坊参加开业典礼，正式红绸、剪刀、礼花与合影。

**大型餐厅**

舞台、主持人、记者、舞狮与大量顾客欢呼。

**全国连锁品牌**

大型红毯、金色剪刀、媒体闪光灯、烟花、无人机灯光表演和全部重要熟客登场。

随着成长，演出必须越来越宏大。

剪彩后切换到新建筑外观，显示新解锁内容。

### 10.3 动画技术要求

- 使用实际多帧动画、补间动画或适当的骨骼动画。
- 禁止只通过瞬间更换整张图片假装完成演出。
- 支持跳过动画。
- 已解锁过场可以在剧情回顾中重新观看。
- 播放动画时不能错误推进营业计时。
- 已观看状态必须写入当前存档。

## 十一、游戏经济与长期经营

### 11.1 初始经济

初始金币：300

参考价格：

- 基础煎饼：18 金币
- 加蛋煎饼：25 金币
- 双蛋特色煎饼：32 金币
- 高级特色煎饼：40–55 金币

食材成本应随配方增加，每单保持合理正利润。

### 11.2 玩家可以赚钱的方式

- 日常订单
- 完美制作奖励
- 熟客小费
- 剧情任务
- 节日活动
- 成就奖励
- 分店被动收入

### 11.3 玩家可以花钱的方式

- 食材补货
- 厨具升级
- 建筑升级
- 室内装修
- 特殊配方解锁
- 分店升级
- 外观收藏

所有物品与升级都必须明确展示价格，不允许金币余额与实际扣款不一致。

### 11.4 经济平衡

设计目标：

- 前 5 天能够买到第一个明显改善体验的升级。
- 第 8 天左右具备进入固定摊位的条件。
- 第 18 天左右解锁正式门店。
- 第 32 天左右解锁大型餐厅。
- 第 48 天左右有机会解锁连锁品牌。
- 玩家不需要完美完成所有订单才能推进游戏。
- 不能因为某次采购或装修而陷入无法营业的状态。

开发时必须模拟至少 50 个游戏日，检测平均收入、食材成本、升级时间、任务奖励和资金不足的情况。

若数值导致升级过慢，应调整收益和升级成本，而不是强迫玩家反复刷相同内容。

## 十二、连锁经营系统

完成第五阶段后解锁独立「连锁分店管理」界面。

- 天津老城区
- 北京商业街
- 上海购物区

分店以独立卡通店铺卡片和区域地图呈现。

每个分店拥有：

- 当前营业收入
- 员工效率
- 装修等级

- 升级费用

分店提供离线于营业画面的被动收入，以游戏日为结算单位，不以现实时间挂机计费。

玩家可以管理分店，但仍然可以进入自己的主店亲手摊煎饼。

分店收入要有上限和经济平衡，避免无限自动增长破坏游戏乐趣。

- 不依赖付费 API 才能运行核心玩法。
- 无法加载个别非关键资源时提供合理降级，不应使整款游戏崩溃。

## 二十、最终质量要求

这是一款真正的经营游戏，而不是功能展示 Demo。

请在开发过程中不断从玩家角度思考：

- 第一局是否容易理解？
- 摊煎饼的操作本身是否有趣？
- 玩家是否能明显感受到厨具升级的价值？
- 新的一天是否有令人期待的内容？
- 熟客是否像真实存在的角色？
- 装修是否具有成就感？
- 每次建筑升级是否值得庆祝？
- 玩了 10 天之后是否仍然有新鲜感？
- 玩了 30 天之后是否仍然有目标？
- 完成主线后是否有继续游玩的动力？

**功能数量不是成功标准，真正的操作乐趣、完整的成长体验、精致的视觉反馈和稳定的运行质量才是。**

立即从检查现有项目开始，建立功能差距清单，然后按计划逐阶段实现、测试、优化，直到交付可玩的完整版本。不要仅生成策划文档、伪代码或静态演示界面。
